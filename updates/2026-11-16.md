# Weekly update: 2026-11-16

Quiet week for referral mechanism papers; the useful finds are a CCS '26 identity paper that makes Sybil resistance grow with use and carry across apps, an x402 referral protocol we hadn't tracked that settles the commission inside the agent's payment, and one more single-level, volume-tiered exchange program.

## Papers
- **Song, Zheng, Gao, Li, Liu & Xiao, *Braid: Sybil-Resistant Decentralized Identity with Trustless Key Recovery and Non-Transferable Anonymous Credentials*, CCS '26, doi:10.1145/3830454.3832631 (published Nov 14)**: on-chain bindings gradually merge one holder's identifiers into an "associated identifier", so fraud by any key is attributable and Sybil resistance grows with interactions and carries across applications, unlike campaign-scoped protection; the same structure gives trustless key recovery (2.41 s association, 3.31 s presentation on consumer devices, authors' figures). [Crossref/ACM](https://doi.org/10.1145/3830454.3832631) → [papers/sybil-resistance](../papers/sybil-resistance.md)

## Competitors / signals

## Product
- Design hooks: (1) for the agent-first register flow, one person can mint many keys cheaply; Braid's pattern suggests linking a holder's keys (agent key, Kernel wallet, delegate keys) into one accountable identity that persists across `groupId`s, so a skiplist on one key reaches the rest; (2) x402-mesh shows the shape of an agent-triggered payout: a single-use token id carried in the payment and reconciled from an on-chain event, plus a delegation-lineage claim the oracle can check before signing `rewardRoots`; (3) RISEx joins edgeX (14-day window) in tiering the rate on the referrer's rolling referred volume, a per-period activity test used as a reward; referralTree could use the same window to decide who stays eligible (the bilinear-cost point from last week).
